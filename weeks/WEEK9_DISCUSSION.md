This round I submitted the next BBO queries with roughly 17+ observations per function (more on higher-D ones). I still choose points with a Gaussian Process plus EI/UCB, but Module 19’s LLM ideas — prompting, decoding controls, token budgets and attention — map cleanly onto how that optimiser is steered.

**Prompting patterns.** Early weeks were close to **zero-shot**: one generic “fit GP, maximise acquisition” instruction for all eight functions. That was simple but vague, so queries drifted to empty high-uncertainty regions and box edges. I then moved to **few-shot** behaviour by conditioning on recent incumbents and failures (for example, “stay near F5’s ridge examples at x₁≈0.38–0.40 with x₂–x₄ high”). Finally I used **structured prompts**: per-function constraints written like system instructions — lock F3’s x₃ near 0.40, keep F6 interior, refuse GP exploit on F1 when signal is absent, and search only inside a trust region around the best point. Structured prompts cut ambiguity; Week 8’s gains on F4 (0.47→0.57), F5 (3744→3760) and F8 (9.865→9.868) came from that tighter brief, not from a wider free-form ask.

**Decoding settings (temperature, top-p, top-k, max tokens).** I do not run an LLM decoder for the portal point; the analogues are acquisition hyperparameters. **Temperature ≈ UCB κ / EI ξ / trust-region radius**: high temperature explores diverse candidates; low temperature concentrates near the mode. After Week 8 I set low temperature on F4/F5/F8 (small local steps from the new bests) and only slightly higher temperature where the last decode failed (F2’s 0.712 step scored 0.63 vs best 0.78). **Top-p / top-k ≈ candidate filtering**: I keep the top acquisition scores inside the trust box and discard boundary artefacts. **Max tokens ≈ step budget / dimensionality focus**: with one query per week I “generate” a short answer — one 6-decimal vector — not a long rambling trajectory, which forces decisive exploit/explore choices.

**Tokenisation and formatting.** Portal strings must be `0.xxxxxx` hyphen-separated. Messy formatting is like bad tokenisation: the system misreads the intent. Edge cases matter the same way token boundaries mangle rare strings — coordinates at 0 or 1 often look like optimiser hallucinations from inflated GP variance, so I penalise them. I also avoid exact duplicate “tokens” (re-sending a fully observed incumbent) because that burns the weekly budget without new information.

**Limits at ~17 points.** More history is a longer context window, but returns diminish. Attention is finite: the GP (and I) overweight recent local structure and can ignore weak global clues — on F1, extra near-zero points do not create a peak. **Prompt overfitting** showed up when I reused a “micro-step everywhere” template; on F6/F2 that template hurt. Irrelevant context is real on F8’s eight inputs — ARD length scales help “attend” to sensitive dimensions and down-weight flat ones, similar to ignoring filler tokens.

**Reducing hallucinations.** Hallucinations here are confident wrong peaks. Mitigations: tighter instructions (constraints), retrieval of prior bests (few-shot incumbents), constrained output format (6 d.p., interior box), and a trust gate — if the surrogate has no signal (F1), I do not exploit its posterior. WhiteKernel on noisy F2 and log-y on F5 are like grounding the model in a better representation so it invents less structure from noise.

**Scaling later.** With larger n I would keep structured per-function prompts but refresh them each round (retire stale locks). For heavier surrogates I would treat hyperparameter search like multi-fidelity LLM tuning: cheap diagnostics first, expensive global searches only for promising configs. Longer context helps only until attention is saturated; then summarisation (incumbent + length scales + last failures) beats dumping every point into the “prompt.”

**Practitioner takeaway.** Black-box work with incomplete information is prompt design under a hard token budget: one evaluation per function per week. Structured prompts and low-temperature decoding justify exploitation where evidence is strong (F4/F5/F8); finite attention and tokenisation-like edge artefacts justify continued exploration where the model is untrusted (F1). The discipline is matching the sophistication of the instruction to the evidence, not decorating thin data with a fluent-looking but hallucinated plan.
